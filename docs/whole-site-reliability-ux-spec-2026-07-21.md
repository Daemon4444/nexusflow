# NexusFlow 整站可靠性与体验迭代 Spec

> 日期：2026-07-21  
> 状态：实施完成，发布候选已通过本地门禁，等待低流量生产发布与版本核对  
> 范围：公开站、用户控制台、管理后台、OpenAI/Anthropic 兼容接口、异步媒体任务、计费、子账号、监控与发布流程

## 1. 目标

本轮不是单页换肤，而是把 NexusFlow 收口成一套一致、可信、可验证的生产产品：

1. 页面在桌面/移动端、明/暗主题下都可读、可操作。
2. 页面对“模型是否真的可调用、参数如何传、失败原因是什么”的描述与后端行为一致。
3. 主账号、子账号、管理员的权限、额度、账单和监控边界清晰。
4. 关键用户旅程有自动化或可重复的生产验收步骤。
5. 发布具备构建门禁、健康检查、版本核对和明确回滚路径。

## 2. 设计原则

视觉方向为 **Quiet Infrastructure / Editorial Console**：

- 以白、墨色和青绿色为主，不用大面积渐变或装饰性动效抢占内容。
- 标题、指标、操作和解释形成清晰层级；减少重复卡片和胶囊标签。
- 公共站突出可信度和快速接入；用户控制台突出下一步操作；后台保持高密度但增加状态识别。
- 只使用现有 React/CSS 组件体系，不在本轮引入第二套完整 UI 框架。
- 明暗主题通过语义色变量实现，不用页面级 `!important` 补丁。
- 动效服从 `prefers-reduced-motion`，交互必须有可见焦点。

## 3. 基线审计

### 3.1 页面与视觉

- 公开页和登录态页面共覆盖 60 个桌面/移动、明/暗组合；基线无页面级崩溃、横向溢出或永久加载。
- 主要视觉问题：
  - 暗色模式存在白色横带、模型文字对比度不足。
  - 移动端文档目录挤占正文首屏。
  - 两套 Header 的结构和状态不一致。
  - 模型页标签过载，价格页不便横向比较，未登录 Playground 缺少明确空状态。
  - 登录后 Activity 在无近期数据时显示大块空图；Key 列表卡片过重。
  - 首次访问任意控制台页会被过时的新手弹窗打断。
  - 登录成功固定跳到账单页，没有保留回跳地址。
  - 后台已删除子账号与正常用户视觉上难以区分。

### 3.2 生产协议与业务功能

已验证通过：

- 控制台真实创建、展示一次性密钥和删除 API Key。
- 错误密钥、掩码密钥、未知模型、模型白名单和资源所有权隔离。
- OpenAI Chat 非流式/流式、Anthropic Messages、Responses CRUD/Input Items。
- Embeddings、TTS、图片生成、上传内容魔数校验。
- TTFT、TPOT、总延迟和用量持久化。
- 账单扣费、CSV 导出、主/子账号用量归属。
- 子账号创建、月额度惰性重置、暂停/恢复、改密、软删除、用户名复用。
- 管理端用户下钻、余额调账并恢复、工单、限流申请、直接限流、模型折扣、供应商/模型读取。

发现的真实契约缺口：

1. `Content-Type: application/json` 的畸形 JSON 被当成 500，应返回稳定的 400 `invalid_json`。
2. 子账号额度耗尽被返回为主账号余额不足，应返回 402 `sub_account_quota_exceeded`。
3. 视频文档使用 `resolution + ratio`，但任务适配器只转发 `size`；`1280x720` 也未规范化为供应商要求的 `1280*720`。
4. 缺少 ARK 凭据时 Seedance 仍以可用模型展示，直到提交后才返回上游 401。
5. 旧 smoke 脚本仍发送错误的视频尺寸格式。
6. 旧 PixVerse/图像/视频兼容轮询接受任意上游 task ID；任意有效 Key 可能读取不属于自己的媒体任务，且旧 PixVerse 创建路径未进入统一预占计费。

## 4. 功能要求

### 4.1 错误语义

- 畸形 JSON：HTTP 400，OpenAI 风格错误体，`code=invalid_json`；不记录为服务器故障。
- 主账号余额不足：HTTP 402，`code=insufficient_balance`。
- 子账号额度不足：HTTP 402，`code=sub_account_quota_exceeded`。
- 子账号暂停：HTTP 403，`code=sub_account_suspended`。
- 计费预留保持数据库原子性；错误原因必须来自同一次原子判定，不以先查后扣代替。

### 4.2 视频参数

- 接受以下输入：
  - `size: "1280*720"`；
  - 向后兼容 `size: "1280x720"` 并规范化；
  - `resolution: "720P" | "1080P"` 与 `ratio: "16:9" | "9:16" | "1:1"`。
- 服务端将语义参数映射成供应商支持的精确尺寸，无法映射时在创建任务前返回 400。
- 文档、Playground 和 smoke 使用同一个公开契约。

### 4.3 模型可用性

- 模型目录区分 `available`、`temporarily_unavailable` 和 `disabled`。
- 对缺少服务端凭据的供应商，用户页明确显示“暂不可用”并禁止发起付费请求。
- 后端在计费预留前返回 503 `provider_not_configured`，不得先扣费或把上游 401 暴露给用户。
- 管理端继续显示不可用模型及原因，便于配置恢复。

### 4.4 身份与导航

- 登录页支持安全的站内 `returnTo`/`callbackUrl`，默认进入 `/dashboard`。
- 已登录用户访问登录页遵循相同规则。
- 外部 URL、协议相对 URL和非法路径不得作为回跳目标。
- 新手引导只在控制台首页出现，文案基于实时模型数据，不写死数量。

### 4.5 公开站与控制台

- 公共 Header 只有一个实现；桌面/移动、登录/未登录状态一致。
- 公开站采用统一的“Routing Observatory”视觉语言：硬网格、路由拓扑、编号坐标和单一青绿色信号；首页、Models、Pricing、Docs 的首屏必须能被肉眼识别为同一产品家族。
- 首页首屏不再使用装饰性模型轮播，改为展示从统一 `/v1` 端点路由到真实模型的拓扑；动效只表达请求流向，并遵守 `prefers-reduced-motion`。
- 模型页优先展示模型名、供应商、类型、上下文和价格；次要能力折叠或弱化。
- 价格页使用可比较的数值列和统一单位，不以 emoji 作为类别主标识。
- 未登录 Playground 显示单一明确的登录行动和能力预览，不出现空白工作区。
- Activity 无数据时显示解释、时间范围和下一步行动。
- API Key 使用紧凑表格/列表；移动端降级为卡片。
- 文档移动端使用可展开目录，正文首屏不被目录占据。

### 4.6 管理端

- 用户表显示主/子账号、active/suspended/deleted 状态；默认隐藏软删除用户，可显式筛选。
- 危险或财务操作继续要求说明，并在成功后刷新真实数据。
- 供应商未配置状态在总览、供应商和模型页一致。
- 空告警、空工单、空审批均有明确空状态。

### 4.7 异步任务所有权

- 图像、视频及 PixVerse 兼容入口创建任务时只向客户端返回 NexusFlow 内部 task ID。
- 轮询必须校验 session/API Key 与任务所属用户；任务不存在时返回 404。
- 不允许为了兼容旧客户端，把未知 ID 当作上游 DashScope/PixVerse task ID 直接查询。
- PixVerse/DashScope 兼容外壳必须委托给统一视频任务管线，复用鉴权、白名单、Provider、预占、结算、失败释放与用量记录。

## 5. 验收矩阵

| 范围 | 必须通过 |
|---|---|
| 静态门禁 | 前后端 TypeScript 构建、前端 lint、计费预留测试 |
| 页面矩阵 | 公开页与控制台桌面/移动、明/暗主题；无崩溃、不可读文字、横向溢出 |
| 身份 | 邮箱登录、子账号用户名登录、回跳、防开放重定向、暂停与改密失效 |
| Key | 创建、一次性明文、掩码拒绝、删除 |
| 文本协议 | Chat 流/非流、Messages、Responses、Embeddings |
| 媒体 | 上传、TTS、图片；视频参数仅做无计费校验，发布后最多一次低成本真实任务 |
| 计费 | 余额预留/结算/释放、子账号额度错误码、折扣、CSV |
| 监控 | TTFT、TPOT、Latency、状态码、模型和 Key 归属 |
| 权限 | 主/子/管理员边界，Responses IDOR 隔离 |
| 后台 | 用户下钻、调账往返、工单、限流、折扣、模型/供应商读取 |
| 发布 | Git clean、远端 SHA、生产 `/api/version`、健康检查、PM2/数据库/Redis |

发布前候选已完成：

- 后端 TypeScript 构建通过；计费预占、子账号失败原因与视频参数契约测试通过。
- 前端 65 个路由生产构建通过；lint 为 0 error（保留 56 条存量 warning）。
- 前后端生产依赖审计均为 0 个已知漏洞。
- 畸形 JSON 返回 400 `invalid_json`。
- 未知内部图像/视频 task ID 在有效 Key 下返回 404，不再尝试上游轮询。
- 旧 PixVerse 创建入口在无渠道环境返回 503，且已委托统一视频管线。
- 首页明/暗主题、模型目录、Pricing、Playground、文档移动抽屉均无横向溢出；暗色轮播遮罩和非默认端口 Pricing 空目录问题已修复。
- 用户反馈第一轮视觉修整不够明显后，公开首页、Models、Pricing、Docs 已完成 V2 视觉重构；桌面和 390px 移动端均以真实浏览器复核，生产式 67 模型目录正常渲染，无横向溢出或页面错误。

## 6. 发布与回滚

1. 仅在北京时间低流量窗口执行生产发布。
2. 发布前记录当前生产 SHA；本地提交并推送后，使用 `scripts/deploy-production.sh`。
3. 脚本必须完成拉取、依赖、前后端构建、迁移、PM2 reload 和健康检查。
4. 发布后核对：
   - `/health`；
   - `/api/version` 与目标 SHA；
   - 公共首页、登录、模型、文档；
   - 一次低成本 Chat 流式请求及 TTFT；
   - 畸形 JSON、额度错误码、视频参数无计费校验。
5. 若健康、登录、计费或核心协议失败，立即回滚到发布前 SHA，并重新构建/reload；不在故障状态继续叠加修改。

## 7. 非目标

- 本轮不更换技术栈，不重写全部页面，不迁移到新的组件库。
- 不改变公开计价策略或现有模型 ID。
- 不自动补齐缺失的第三方凭据；只把不可用状态准确呈现。
- 不删除历史账单、监控或软删除账号的审计记录。
